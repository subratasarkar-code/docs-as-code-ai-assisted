❓ Technical Q&A & Operational Insights

OML executes machine learning algorithms directly inside the database kernel. It completely eliminates data egress to external Python servers or clusters, honors all database security policies, and allows predictions to be generated directly inside SQL views.

Using DBMS_RANDOM.VALUE() inside a view or CTAS query: records with random values <= 0.8 are assigned to the 'TRAIN' partition (~80%), and records > 0.8 are assigned to the 'TEST' partition (~20%).

Using native SQL analytical functions: PREDICTION(CLAIM_DENIAL_GLM USING *) returns the predicted binary label ('Y'/'N'), and PREDICTION_PROBABILITY(CLAIM_DENIAL_GLM, 'Y' USING *) returns the exact confidence score.

ALGO_NAME was set to ALGO_GENERALIZED_LINEAR_MODEL, and PREP_AUTO was set to PREP_AUTO_ON to enable automatic data preparation for missing values and normalization.
