PL/SQL Collection Types Comparison

Associative Arrays • Varrays • Nested Tables

In PL/SQL, Associative Arrays , Varrays (Variable-Size Arrays), and Nested Tables are the three primary collection structures used to manage composite data. While all three store ordered elements of the same datatype, they differ fundamentally in persistence , indexing capabilities , memory layout , and SQL integration .

2. Deep Dive & Implementation Details

A. Associative Arrays (Index-By Tables)

Associative arrays are purely temporary, in-memory structures built for high-performance lookup tables during procedure or package execution.

• Strengths: Dynamic sizing without requiring initialization constructors or EXTEND calls. Supports string keys (e.g., indexing by employee ID or GUID).

  • Limitations: Cannot be defined as database schema objects or stored inside database table columns.

-

DECLARE

sql 
-- Indexed by integer or string key
TYPEt_lookupIS TABLE OFVARCHAR2(100)INDEX BYPLS_INTEGER;
  v_cache t_lookup;
sql 
BEGIN
sql 
  v_cache(10) := 'Active';   -- Sparse key allocation
  v_cache(42) := 'Pending';  -- No EXTEND or initialization required
END;
/

B. Varrays (Variable-Size Arrays)

Varrays are ordered collections designed for scenarios where the maximum number of items is strictly known ahead of time.

  • Strengths: Guarantees element order retention when persisted and retrieved from database columns.
  • Limitations: Fixed upper bound defined at declaration. Always strictly dense—intermediate elements cannot be deleted individually.
sql 
DECLARE
TYPEt_phonesIS VARRAY(5) OFVARCHAR2(20); -- Fixed cap of 5
  v_list t_phones := t_phones();               -- Constructor initialization
BEGIN
  v_list.EXTEND;
  v_list(1) := '+1-555-0199';
END;
/

C. Nested Tables

Nested tables model single-column relational tables within memory or column data, seamlessly blending PL/ SQL logic with SQL set operations.

  • Strengths: Unbounded dynamic growth. Native support for set operations (e.g., MULTISET UNION , MEMBER OF , CARDINALITY ).
  • Limitations: When stored in database columns, element order is not inherently preserved unless explicitly retrieved with an ORDER BY clause.

DECLARE

sql 
TYPEt_tagsIS TABLE OFVARCHAR2(50); -- Unbounded dynamic collection
  v_tags t_tags := t_tags('SQL', 'PLSQL'); -- Constructor initialization
BEGIN
  v_tags.EXTEND;
  v_tags(3) := 'Performance';
  v_tags.DELETE(2); -- Can become sparse upon intermediate deletion
END;
/

3. Selection Strategy Guide

Architecture Decision Tree

  • Use Associative Arrays when: Building fast internal caching mechanisms, key-value mapping (e.g., indexing by VARCHAR2 keys), or temporary logic within PL/SQL procedures.
  • Use Varrays when: Storing fixed small collections where insertion order must be strictly preserved on disk (e.g., historical audit logs, up to 5 contact numbers per user).
  • Use Nested Tables when: Manipulating dynamic, unbounded datasets, performing high-level SQL set manipulations, or storing child collections directly within database table columns.
